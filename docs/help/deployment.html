Operator & administrator manual

Live deployment on the free stack

Recommended: Cloudflare Pages for static React assets and Supabase for PostgreSQL, Auth and the Data API. A separate Express/server VM is not required: writes execute in database functions. PostgreSQL supplies relational constraints, reporting queries and transactions for library operations.

1. Create the database

  1. Create an RBMI-owned Supabase project in an appropriate region. Keep the database password in an institutional password manager.
  2. In Supabase SQL Editor run supabase/migrations/202610090001_library.sql, followed by supabase/seed.sql, once in an empty project.
  3. The seed adds five institutions and category policies only. It does not create sample patrons or default login passwords.
  4. Ensure the Data API exposes only the intended public schema; do not expose app. The migration removes anon/authenticated direct access to that schema and enables RLS on all its tables.
  5. Disable public signup in Auth settings. Create the first operator through Auth > Users.
  6. Copy that user's UUID. Replace the placeholder in scripts/bootstrap-admin.sql and execute it in SQL Editor. This assigns admin in all five campuses. Choose fewer campuses in that trusted SQL if the operator should manage fewer.

Optional CLI route

Install the Supabase CLI using its official installation instructions. With a Docker-supported local environment, supabase start and supabase db reset create the local schema and institutional seed. For a remote project:

supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase db push
# Execute supabase/seed.sql in SQL Editor once after initial schema creation.

CLI tokens and database passwords must not be committed. This project's config disables signup and uses PostgreSQL 15 for local development. Hosted projects may use a newer supported PostgreSQL version; verify migration compatibility before go-live.

2. Configure React

# .env.local (copy .env.example)
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_PUBLISHABLE_OR_ANON_KEY

Both values must be set together. These are public client configuration, not database credentials. Never place a service-role key, secret key or database password in a VITE variable. A build with both blank deliberately opens the demonstration.

Run the production build and test live sign-in locally. An authenticated user without a membership sees a clear membership error. Use Settings to assign additional users after creating their Auth identities.

3. Publish the frontend

  1. Commit the source and lockfile to an RBMI-controlled repository, excluding .env.local and node_modules.
  2. In Cloudflare Workers & Pages, create a Pages project from the repository.
  3. Build command: npm ci && npm run build. Output directory: dist. Set Node version to a supported version satisfying package.json.
  4. Set both VITE variables in the production build environment. Preview deployments require their own intended environment values. Rebuild after any variable change.
  5. Deploy. Set Supabase Auth's Site URL to the resulting HTTPS URL and configure approved redirect URLs if using emailed invitations/password recovery.
  6. Configure a custom domain through Cloudflare if desired. Verify HTTPS and that requests to frontend routes return the app.

For direct upload instead of Git integration, build locally with live environment values and run npx wrangler pages deploy dist --project-name rbmi-library after Cloudflare authentication. Wrangler may prompt to create the project. The provided wrangler.toml specifies dist.

Free-tier limits, checked 9 October 2026

Supabase Free currently has a 500 MB database, 50,000 monthly active users, 5 GB egress and two active projects; low-activity projects can pause after a week. Automatic database backups are excluded. Cloudflare Pages allows 500 builds/month on Free and free unlimited static requests, subject to platform limits including 25 MiB per asset. This app uses no Pages Functions. Neon announced 1 GB/project free PostgreSQL storage on 2 October 2026, but would require adapting the Auth/API layer. Render Free web services sleep after 15 minutes; no such separate API is needed here.

Research links: Supabase pricing; Cloudflare limits; Neon announcement; Render Free. Keep usage under limits and maintain your own off-site backup. A hosted Sites demonstration is a separate private sample-data deployment; it does not provision the institution's live database.
