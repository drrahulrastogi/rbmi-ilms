Backups, restore & go-live acceptance

Database backups

Supabase Free currently has no automatic database backup entitlement. Schedule an institution-owned backup outside this app, encrypt it and keep it off-site. Browser CSV exports are not a complete backup. Store database credentials outside command arguments/source; use an approved PostgreSQL password file with appropriate permissions or a password manager integration.

# Configure connection and secure credential handling first.
# pg_dump custom format preserves schema, constraints and data.
pg_dump --format=custom --no-owner --file=rbmi-backup.dump YOUR_APPROVED_CONNECTION
# Restore only into a prepared isolated test project, never over production blindly.
pg_restore --no-owner --no-acl --dbname=YOUR_TEST_CONNECTION rbmi-backup.dump

Coordinate Supabase-specific Auth/storage backup requirements with the current Supabase documentation. A database dump alone may not cover all platform configuration or external storage. This release stores no uploaded file assets or book covers. After restore, check Auth identities, memberships, policy rows, copy states, open loans, fines and audit. Keep migration history and deployed source/version separately.

Acceptance checklist

  1. Create named accounts for admin, librarian, assistant, accountant, auditor and patron. Verify allowed actions and rejected actions.
  2. Verify each campus sees only its own records; patron accounts see only their own profile/loans/holds/fines.
  3. Issue a barcode, reject a duplicate issue, return it, renew within the cap and reject after the cap.
  4. Check an inactive/expired patron, maximum loans, overdue block and assessed-fine balance block.
  5. Test FIFO hold priority and renewal blocking.
  6. Test weekend/holiday/grace/cap fine examples agreed by RBMI.
  7. Collect a part payment and waiver, verify receipts, reason and audit; reject overpayment.
  8. Import valid books/students; verify a conflicting row rolls the full batch back.
  9. Receive an order once and scan/close a stock session; inspect missing-vs-loaned distinctions.
  10. Test two simultaneous operators and an unknown-result network interruption; verify constraints and operator recovery.
  11. Print and scan labels using your actual devices; print a return receipt.
  12. Restore an encrypted backup to a test environment and compare key record counts.

Only promote real institutional data after these checks. The shipped local engine tests do not replace a hosted multi-connection load test. For a large catalogue or growing audit history, add server pagination and measure query/memory/egress before capacity becomes a problem.
