Holds and reservation priority

Holds reserve a bibliographic title within a library, using a FIFO waiting queue ordered by creation time and identifier.

How to use this section

  1. Choose Holds > Place hold, or Place hold in a title's copy drawer. Select a title and enter an active, unexpired patron code.
  2. Review queue position, placement time and status. The same patron cannot have duplicate waiting holds on the same title.
  3. Issue the next available copy to the first waiting patron. The server blocks queue bypass and marks the hold fulfilled when issued.
  4. Cancel unwanted waiting holds. Staff manage the library queue; patrons manage only their own holds.

Notes and limits

A waiting hold blocks renewals of that title.

Pickup-expiry timers, automatic notification emails and inter-library transfers are not implemented. Use the approved institutional contact procedure.

Worked example: a book is already borrowed

All copies of Fundamentals of Nursing are on loan in RBCN. Student A places a hold at 10:00, followed by Faculty B at 10:05. The title's waiting queue is A first, then B; this implementation uses arrival order rather than a faculty priority.

  1. When a copy returns, it becomes available. The hold itself does not issue a book automatically.
  2. The librarian checks the queue and issues a copy of that title to A. The issue operation marks A's waiting hold fulfilled.
  3. B becomes first in the remaining queue. If A cancels before issue, B moves to the front immediately.
  4. A waiting hold blocks renewal of that title under the current rules, so an existing borrower cannot keep extending it ahead of the queue.

A hold reserves the next eligible copy of a title, rather than a particular accession. It belongs to one library. It does not transfer a copy from another library. Waiting holds do not expire automatically; staff should cancel them only under their institutional procedure.
